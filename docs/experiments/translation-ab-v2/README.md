# 翻译扩展排版修复：一次配对开发观察

日期：2026-10-20，America/Vancouver。GeneralRouter v0.1.7；宿主为 DSH Desktop 0.2.1-rc.2。

**结果：B 使用的 GPT 路由 token 少了约 55.8%，但目录翻译未达标，总 token 和完整开发回合耗时均上升。这次没有达到“保持交付质量并缩短工期”的目标。** A 的目标覆盖更完整，两组都没有被认定为全页无缺陷。

这是一个任务、每组一次执行的工程案例，不是统计评测。数字取自保存的主会话和关联子会话；效果取自用户提供的截图和操作确认。开发者没有追加运行验收。

## 问题与共同任务

已有浏览器翻译扩展在 arXiv 论文的“仅译文”模式下，存在目录未翻译、中文阅读排版不理想和表格变窄的问题。本次修复页面固定为 [Attention Is All You Need，arXiv HTML v7](https://arxiv.org/html/1706.03762v7)。该链接说明目标页面，不代表我们在收尾时重新抓取或测试了网页。

主要目标在执行前确定：

1. 目录复用对应正文标题的译文，保留章节编号、层级、顺序及跳转。
2. 改善中文字体回退与行距，保留公式、代码、上下标等内容的排版。
3. 保持表格相对于正文的宽度及居中，改善表头和窄窗口显示。

正文、公式及编号、引用和恢复重译为保护项。指定观察范围包括摘要、Introduction 前两段、3.2.1 与公式（1）、Table 1；截图同时提供可见目录作为证据。正常的中英长度差异和随之变化的段落高度不算错误。

两组从同一份旧源码分别复制，使用相同的六张起点截图、任务要求和十分钟开发预算。主 agent 均为 GPT-6.1 Sol / max，各派出一个开发 subagent，没有另派 reviewer。开发期间禁止运行测试、构建、浏览器自动化或翻译请求；真实浏览器操作由用户在交付后完成。两组先后执行、会话独立，要求不访问另一组产物。没有重新运行以挑选更好的结果。

修复对象是扩展的 DOM/CSS 与恢复逻辑。翻译接口、模型、参数和提示词要求保持不变；截图中的运行时模型标签为 `gemini-3.5-flash-lite`，不是开发子 agent 的模型。上游实际模型未独立核实。先前计划的 Hy-MT2 本地翻译 App 未在本次执行。

B 的任务向量为 `(0.10, 0.85, 0.05, 0.00)`，顺序为 agentic、coding、knowledge_document、scientific_reasoning，来源为 `planner_estimated`。它表达任务的能力侧重，不是实测难度或成功率。

必须区分三层范围：资料库有 12 组配置；DSH 原生 subagent 的显式允许列表只配置了 Flash；宿主同时暴露 `subagent_codex` 与 `subagent_antigravity`，用户确认其他模型位于这些插件中。因此不能把原生允许列表写成“整个宿主只有 Flash”。

保存的本次匹配记录显示：12 组配置都有能力评分，Argon high 排第一（0.5627408193），Flash high 排第十二（0.3985348336）；其余 11 组都因 `route_not_in_this_session_model_allowlist` 被排除，Flash 是本次原生路径唯一通过准入的候选。返回结果要求调用原生 `subagent`，实际也只调用了该入口一次；另外两个插件入口调用次数均为零，`route_mismatch=false`。Flash 的适用额度仍未知，没有被推定为无限或足够。

因此，这轮反映的是当前原生派遣路径的表现，**没有验证跨三个入口的完整选模，也不是从 12 个可执行候选中为降低成本而选中 Flash**。这份记录不足以把入口缺席的根因定为用户配置错误或实现缺陷。完整评分、准入和日志位置见 [汇总数据](results.json) 的 `routing_evidence`。

本次 A 是“省略参数后继承模型”的基线，不代表 DSH 所有原生动态选模方式。模型身份来自宿主请求配置与会话记录，不是子 agent 自报；代理服务内部是否另有模型别名映射仍未知。

## 结论与限制

这个案例说明，降低强模型使用量并不自动带来更少的总 token、更短的完整开发回合或完整的交付质量。B 的目录要求未满足，所以不报告“同质量节省”，也不将 2.3% 的小计差异解释为已建立的成本优势。

一次配对执行无法隔离模型随机性、执行入口、规划开销与候选限制的影响。两组顺序运行，外部服务负载和缓存条件没有被控制；截图覆盖有限，人工观感不是盲评。原生与插件入口的差异必须与能力评分区分。不能据此推断某个模型或路由策略在其他任务中的总体效果。

v0.1.7 在此收尾。保留当前算法、两组源码和原始证据；没有继续修复、重跑或根据这个单一样例调整权重。后续真实使用应先补齐不同入口的候选覆盖和更多独立任务结果，再决定是否引入成本/耗时/effort 策略。
